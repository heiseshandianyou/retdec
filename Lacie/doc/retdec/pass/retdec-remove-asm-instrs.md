# LLVM Pass: retdec-remove-asm-instrs

`retdec-remove-asm-instrs` 是一个清理性质的 Pass，负责移除反编译初期用于机器码映射的占位指令，并将地址信息固化为 LLVM 元数据。

## 核心功能

1.  **地址元数据转换**：在解码阶段，每一条机器指令对应的 LLVM IR 块都会通过特殊的伪指令进行锚定。该 Pass 将这些锚定信息转化为 LLVM 标志性的元数据（`insn.addr`），附加到每条指令上。
2.  **清理映射指令**：移除所有不再需要的汇编映射伪指令，使 IR 回归标准的 LLVM 语义。
3.  **内存管理**：释放解码期间缓存的 Capstone 指令数据，减少内存占用。

## 算法原理

### 1. 元数据标注
- 遍历模块中的所有函数。
- 使用 `AsmInstruction` 迭代器遍历所有汇编指令块。
- **获取地址**：从汇编块对象中提取其在原始二进制文件中的 64 位虚拟地址。
- **附加元数据**：为该块内包含的所有 LLVM 指令调用 `setMetadata("insn.addr", ...)`。这使得即使后续指令执行了重排或移动，其原始地址信息依然可查。

### 2. 移除伪指令
- 找到 LLVM IR 中表示“汇编-LLVM映射”的特殊对应指令（通常是某个特定的全局变量或存储操作）。
- 从其父级基本块中彻底删除这些指令（`eraseFromParent`）。

### 3. 环境清理
- **释放 Capstone 资源**：通过 `cs_free` 释放反编译引擎内部维护的指令信息 Map。
- **移除全局变量**：如果模块中存在专门用于映射跟踪的特殊全局变量（且其引用计数已归零），则将其从模块定义中移除。

## 算法流程

1.  初始化 LLVM 模块和上下文。
2.  循环遍历所有函数：
    - 遍历每一个汇编指令范围。
    - 为范围内的每条 LLVM 指令设置 `insn.addr` 元数据。
    - 删除范围起始的映射标记指令。
3.  遍历 `LlvmToCapstoneInsnMap`，逐一调用 `cs_free`。
4.  清理模块级别的全局映射辅助变量。

## 源码位置
- `third_party/retdec/src/bin2llvmir/optimizations/asm_inst_remover/`

## 总结
该 Pass 标志着 RetDec 从“二进制感知”阶段向“纯粹 IR 优化”阶段的过渡。它通过将底层的地址信息下沉到元数据层，既保留了逆向分析所需的关键追溯能力，又消除了非标准指令对后续 LLVM 标准优化 Pass 的干扰。
