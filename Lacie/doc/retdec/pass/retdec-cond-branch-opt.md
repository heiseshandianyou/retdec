# LLVM Pass: retdec-cond-branch-opt

`retdec-cond-branch-opt` 负责将机器指令中基于标志位（Flags，如 ZF, SF, OF, CF）的低级跳转逻辑还原为高级语言中的直接比较逻辑（如 `if (a <= b)`）。

## 核心功能

1.  **标志位语义提升**：在二进制反编译的早期阶段，跳转指令往往依赖于前序指令设置的处理器标志位。该 Pass 通过分析这些标志位的来源，将复杂的逻辑组合（如 `(SF ^ OF) | ZF`）提升为简单的 LLVM 比较指令（`icmp sle`）。
2.  **代码化简**：移除冗余的标志位计算指令，使控制流图（CFG）更加简洁，更接近源代码的逻辑。

## 算法原理

### 1. 基础分析
- 运行 **到达定值分析（Reaching Definitions Analysis, RDA）**，用于追踪寄存器（特别是标志位寄存器）在函数内的值流向。

### 2. 符号树构建与模式匹配
- 对于每个条件跳转指令，基于其条件操作数构建 **符号树（Symbolic Tree）**。
- 符号树会递归回溯，直到找到产生标志位的根源指令（通常是 `sub` 或 `cmp`）。
- **模式匹配（Pattern Matching）**：在符号树上匹配特定的布尔逻辑组合。例如：
    - **SLE (<=)**：匹配模式 `(SF ^ OF) | ZF`。
    - **SLT (<)**：匹配模式 `SF ^ OF`。
    - **SGT (>)**：匹配模式 `!((SF ^ OF) | ZF)`。
    - **SGE (>=)**：匹配模式 `!(SF ^ OF)`。
    - **NE (!=)**：匹配模式 `!ZF`。

### 3. 指令转换
- 当匹配成功时，Pass 会提取出原始的两个参与比较的数值（例如 `sub` 指令的两个操作数）。
- 使用 `ICmpInst` 创建一个新的比较指令，直接比较这两个数值。
- 将跳转指令的条件替换为这个新的比较结果。
- 为了辅助后续的 `mem2reg` 优化，可能会通过临时的 `alloca` 系统来重新组织这些值。

## 算法流程

1.  初始化 RDA 分析。
2.  遍历模块中的所有函数和指令。
3.  筛选出条件跳转指令（`BranchInst`）。
4.  对跳转条件运行符号树匹配。
5.  如果识别出已知的标志位组合，则调用 `transformConditionSub` 执行替换。
6.  递归清理掉不再使用的旧条件指令。

## 总结
该 Pass 解决了反编译中一个关键的“语义鸿沟”问题。通过理解处理器架构特有的标志位组合涵义，它成功地将底层汇编逻辑转化回了程序员易于理解的高级关系运算。
