# retdec-param-return

`retdec-param-return` 是 RetDec 中的一个关键 LLVM Pass，用于自动推断和重建函数的参数个数、参数类型以及返回值。

## 功能概述

在二进制反编译中，函数调用最初往往没有明确的参数列表（在 LLVM IR 中表现为 `call` 指令没有任何操作数）。`retdec-param-return` 的目标是通过分析函数内部对寄存器的使用以及调用方在调用前对寄存器的设置，还原出符合 ABI（应用二进制接口）的函数签名。

## 算法流程

该 Pass 的算法是一个多阶段的启发式分析过程：

1.  **数据收集（Collection）**：
    -   遍历模块中的所有函数调用和定义。
    -   利用 `Collector` 寻找可能的参数来源（调用前的寄存器写操作）和返回值来源（函数返回前的寄存器写操作）。
    -   利用 RDA（到达定值分析）来确认这些寄存器操作是否真的影响了函数调用或从函数返回。

2.  **多源信息集成（Information Integration）**：
    -   **LTI (Library Type Information)**：如果识别出是标准库函数，直接使用预定义的签名。
    -   **调试信息**：如果存在 DWARF 等调试信息，优先使用其中定义的参数和返回值。
    -   **符号导出/配置**：从导出表或用户提供的配置文件中获取已知签名。
    -   **名字修饰（Demangler）**：对于 C++ 函数，通过反修饰（Demangle）函数名来提取参数和返回值类型。

3.  **启发式过滤（Filtering）**：
    -   根据特定架构的调用约定（Calling Convention，如 cdecl, stdcall, fastcall 等）对收集到的潜在参数进行过滤。
    -   过滤掉那些虽然在调用前被修改但实际上不是参数的寄存器。
    -   处理可变参数函数（Variadic functions）。

4.  **包装分析（Wrapper Analysis）**：
    -   识别“包装函数”（Wrappers），即那些仅仅是为了调用另一个函数而存在的函数。将包装函数的参数与被调用函数的参数进行关联和传播。

5.  **类型修改（Type Modification）**：
    -   基于收集到的信息，尝试进一步精细化参数和返回值的类型（如指针、整型等）。

6.  **IR 应用（Apply to IR）**：
    -   **修改函数定义**：更新 LLVM `Function` 的签名，添加识别出的参数。
    -   **修改调用点**：更新所有 `CallInst`，将识别出的参数作为操作数传入。
    -   **返回值处理**：如果函数有返回值，将识别出的返回值来源转换为 LLVM 的 `ret` 指令返回值。

## 相关文件

-   `param_return.cpp`: Pass 的核心控制器。
-   `collector.cpp`: 负责底层的数据流和寄存器使用收集。
-   `filter/`: 包含针对不同调用约定的过滤逻辑。
-   `demangler/`: 提供 C++ 函数名反修饰支持。

## 总结

`retdec-param-return` 是让反编译代码从“汇编风格”转向“类 C 风格”的核心。它不仅还原了函数的外部接口，还为后续的类型传播和高级语义分析（如数据结构重建）提供了基础。
