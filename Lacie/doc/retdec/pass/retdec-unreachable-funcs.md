# retdec-unreachable-funcs

`retdec-unreachable-funcs` 是 RetDec 中的一个 LLVM Pass，用于通过调用图分析移除模块中不可达（Unreachable）的函数定义。

## 功能概述

在反编译大型二进制文件时，由于静态分析的局限性，可能会识别出大量永远不会被执行的函数，或者是为了逆向某些库而引入的无关函数。这个 Pass 的目的是清理这些冗余函数，从而缩小反编译的范围，提高生成的代码质量和可读性。

## 算法流程

该 Pass 基于调用图（Call Graph）分析，核心算法逻辑如下：

1.  **预检查**：
    -   如果目标是共享库（Shared Library）或目标文件（Object File），或者是配置中要求保留所有函数（`keep-all-functions`），则跳过该 Pass，因为这些情况下的可见性难以完全确定。
    -   获取程序的主函数（`main`）。如果找不到主函数或主函数只是一个声明，则中止优化。

2.  **构建调用图**：
    -   利用 LLVM 的 `CallGraphWrapperPass` 构建整个模块的调用图。

3.  **计算不可优化（可达）函数集**：
    -   **主函数及其衍生**：将 `main` 函数标记为不可优化。利用 `ReachableFuncsAnalysis` 找出从 `main` 函数开始在调用图中所有可达的、有定义的函数。
    -   **全局可达函数**：找出被全局变量（如函数指针表）引用而可能被全局调用的函数。
    -   **特殊约束**：
        -   保留所有函数声明（Declarations）。
        -   递归检查函数的使用者（Users）。如果有任何使用者是不可优化的指令或常量表达式，则该函数本身也被视为不可优化。

4.  **移除可优化（不可达）函数**：
    -   遍历模块中的所有函数。
    -   如果一个函数不在“不可优化函数集”中，说明它是从程序入口不可达的孤立函数。
    -   **执行移除**：
        -   从调用图中移除该函数节点。
        -   将该函数的所有使用处（如果有）替换为 `UndefValue`。
        -   删除函数体（`deleteBody`），从而减少内存占用和后续 Pass 的开销。

## 相关文件

-   `unreachable_funcs.cpp`: Pass 的主要控制逻辑。
-   `reachable_funcs_analysis.cpp`: 提供具体的可达性分析算法（在 `analyses` 目录下）。
-   `unreachable_funcs.h`: 类定义。

## 总结

`retdec-unreachable-funcs` 是反编译流程中的一个重要“剪枝”步骤。它通过识别并移除代码中的死函数，不仅让反编译结果更加聚焦于核心逻辑，还显著减轻了后续数据流分析和结构化分析的计算压力。
